# Shelldex Project YAML Schema

Each project is a single `.yml` file in `src/data/projects/`.

---

Only runnable AI agents belong in Shelldex. A user must be able to give the shipped assistant a goal and have it choose and carry out actions. OpenClaw and Hermes Agent qualify. Tools for other agents never qualify, including plugins, memory libraries, registries, dashboards, orchestration layers and deployment wrappers.

## Required Fields

| Field         | Type       | Description                                                   |
|---------------|------------|---------------------------------------------------------------|
| `name`        | `string`   | Display name of the project                                   |
| `ecosystem_role` | `string` | Agent relationship: reference, fork, reimplementation, derivative, or alternative |
| `slug`        | `string`   | URL-safe identifier (used in `/projects/{slug}`)              |
| `tagline`     | `string`   | One-line pitch (shown on cards)                               |
| `description` | `string`   | Longer description (1–3 sentences)                            |
| `language`    | `string`   | Primary language — one of: `typescript`, `rust`, `python`, `go`, `c`, `bash`, `zig`, `javascript`, `kotlin`, `multi` |
| `category`    | `string[]` | One or more categories (e.g. `[security, lightweight]`)       |
| `status`      | `string`   | One of: `active`, `experimental`, `archived`                  |
| `highlight`   | `string`   | Key selling point or notable metric                           |
| `ecosystem_role` | `string` | reference, fork, reimplementation, derivative, or alternative |
| `emoji`       | `string`   | Single emoji representing the project                         |
| `added`       | `string`   | ISO date when the project was added (`YYYY-MM-DD`)            |

## Optional Fields

| Field     | Type     | Description                                    |
|-----------|----------|------------------------------------------------|
| `github`  | `string` | GitHub repo in `owner/repo` format             |
| `quick_start` | `string` | Upstream setup URL (HTTP or HTTPS); required for current agents |
| `first_task` | `string` | A concrete task a newcomer can try; required for current agents |
| `website` | `string` | Project homepage URL                           |
| `tier`    | `number` | Agent lineage: `1` reference/fork/reimplementation, `3` derivative/alternative. The former tool tier (2) is retired.                 |

## Enriched Fields — `github_data`

Added automatically by `pnpm run enrich`. **Do not edit manually.**

```yaml
github_data:
  stars: 228000           # Current stargazers count
  forks: 14200            # Fork count
  open_issues: 842        # Open issues and pull requests
  license: MIT            # SPDX license identifier (or null)
  topics:                 # GitHub repo topics
    - ai
    - agent
    - self-hosted
  last_commit: "2026-02-27T18:30:00Z"          # pushed_at timestamp
  latest_release: "v4.2.1"                      # Tag name of latest release (or null)
  latest_release_date: "2026-02-20T12:00:00Z"   # Release publish date (or null)
  star_growth_7d: 1200                          # Stars gained in last 7 days (or null if no history)
  last_enriched: "2026-02-28T10:00:00Z"         # ISO timestamp of last enrichment run
```

| Field                 | Type              | Description                                              |
|-----------------------|-------------------|----------------------------------------------------------|
| `stars`               | `number`          | Current stargazer count from GitHub API                  |
| `forks`               | `number`          | Fork count                                               |
| `open_issues`         | `number`          | Open issues and pull requests combined                                        |
| `license`             | `string \| null`  | SPDX license ID (e.g. `MIT`, `Apache-2.0`)              |
| `topics`              | `string[]`        | GitHub repository topics                                 |
| `last_commit`         | `string`          | ISO timestamp of the repo's last push                    |
| `latest_release`      | `string \| null`  | Tag name of the latest GitHub release                    |
| `latest_release_date` | `string \| null`  | ISO timestamp of the latest release                      |
| `star_growth_7d`      | `number \| null`  | Net change vs. the snapshot exactly 7 days earlier; null if absent      |
| `last_enriched`       | `string`          | ISO timestamp of when enrichment last ran                |


### Repository activity indicators

| Indicator              | Meaning                                                              |
|------------------------|----------------------------------------------------------------------|
| `issues_stars_ratio`   | `open_issues / stars` — open issues and pull requests per star; null when stars are zero. Low <1%, moderate 1–<5%, high ≥5%. This is issue load, not a health or safety verdict |
| `days_since_last_release` | Days since the latest GitHub release (null if no releases)        |
| `days_since_last_commit`  | Days since the repo was last pushed to                            |

## Supporting files and refresh

- `src/data/star-history.json`: observed repository totals by date, used for seven-day net change.
- `src/data/star-activity.json`: surviving stars by the day they were added. These counts back the daily charts and do not reconstruct net growth.
- [Methodology and corrections](https://shelldex.com/methodology/) defines the score, historical records and missing data.

Use `pnpm run enrich:vault` for an authorized full metrics refresh. An ordinary build reads saved data. See [DEPLOYMENT.md](DEPLOYMENT.md).
